# Recent Changes

## 2026-09-11

### Visual Query Builder

New component for building filters visually in companies, contacts and deals lists.

**Files added:**
- `apps/app/components/data-table/visual-query-builder.tsx` - Popover-based UI with AND/OR support
- `apps/app/components/data-table/vqb-types.ts` - Types and field definitions (COMPANY_VQB_FIELDS, CONTACT_VQB_FIELDS, DEAL_VQB_FIELDS)
- `apps/app/components/data-table/vqb-serializer.ts` - URL persistence via nuqs (serializeVqb, deserializeVqb, vqbSummary, compileVqbToQuery)

**Features:**
- AND/OR conjunction switching between clauses
- Field selection with type-appropriate operators
- Value input (text or select) per field
- URL persistence so filter views are shareable links
- Inspired by Gridex Visual Query Builder

**Wired to:**
- `apps/app/app/(app)/companies/companies-table.tsx`
- `apps/app/app/(app)/contacts/contacts-table.tsx`
- `apps/app/app/(app)/deals/deals-table.tsx`

### Multi-Provider AI Endpoints

Extended model provider support beyond Vercel AI Gateway and Ollama. All providers are optional and route through the AI Gateway when available.

**Environment variables (documented in `.env.example`):**
- `OLLAMA_BASE_URL` / `OLLAMA_MODEL` - Local Ollama server (OpenAI-compatible)
- `LMSTUDIO_BASE_URL` / `LMSTUDIO_MODEL` - LM Studio local server (OpenAI-compatible)
- `LLAMA_CPP_BASE_URL` - llama.cpp local server (OpenAI-compatible)
- `OPENCODE_API_URL` / `OPENCODE_API_KEY` - Opencode/Zen gateway
- `OPENROUTER_API_KEY` / `OPENROUTER_MODEL` - OpenRouter hosted models
- `REPLICATE_API_TOKEN` - Replicate inference endpoint

**Files updated:**
- `.env.example` - Added documentation for all new provider variables
- `apps/api/src/config/env.validation.ts` - Added Joi validation for new env vars
- `apps/api/turbo.json` - Added new variables to `globalPassThroughEnv`
- `apps/agent/agent/lib/capabilities.ts` - Added capability entries for each provider

### Research Search Alternatives

Perplexity has been replaced by a multi-provider search approach. The agent can now use any combination of:

- Tavily (`TAVILY_API_KEY`) - Semantic web search with citations
- Exa (`EXA_API_KEY`) - Semantic search and research
- Brave Search (`BRAVE_API_KEY`) - Privacy-focused search
- Firecrawl (`FIRECRAWL_API_KEY`) - Web scraping and content extraction
- Google Custom Search (`GOOGLE_API_KEY` + `GOOGLE_CSE_ID`) - Traditional search API

### Viability Scoring Thresholds

The viability assessment system in `packages/db/src/viability.ts` uses weighted scoring optimized for the Germany/Switzerland pilot:

| Component | Score if Present |
|-----------|------------------|
| Mobile phone | 65 |
| Direct landline phone | 55 |
| Valid email | 25 |
| Has name | 10 |

**Threshold values:**
- `evaluateOsintRequirement()`: score < 50 triggers OSINT investigation
- `segmentFeasibility()`: averageScore < 50 or missingPhonePercent > 50 requires OSINT

**Country support:** Germany (DE) and Switzerland (CH) with country-specific mobile prefix detection.

### Legacy CRM Coexistence

The CRM now supports side-by-side operation with legacy database systems via the `crm_legacy` schema and `legacy_map` custodian table.

**Schema:** `scripts/crm_legacy_schema.sql` creates 22 legacy tables in `crm_legacy` schema:
- `companies`, `clients`, `client_notes`, `client_contacts`, `client_audit`
- `client_shares`, `users`, `groups`, `group_permissions`, `lists`
- `statuses`, `stocks`, `company_employees`, `positions`, `dnc_list`
- `phone_types`, `call_log`, `call_campaigns`, `list_duplicates`
- `countries`, `refs`, `trunks`
- `legacy_map` (public schema) - Maps legacy records to Prisma IDs

**Import script:** `packages/db/scripts/import-legacy.ts` migrates data from CSV dumps:
- `companies_dump.csv` → `Company` records
- `clients_dump.csv` → `Contact` + `Activity` records
- `clients_notes_dump.csv` → Standalone `Activity` records
